# 代码走读：一次任务在 MewCode 里是怎么跑完的

这份文档按“跟着一次任务走一遍”的顺序讲清每个文件的角色，
适合第一次读这个仓库的人（也适合作者自己复习）。

## 场景

用户在终端输入：

```
python -m mewcode "在当前目录创建一个冒泡排序脚本并运行验证"
```

## 第 0 站：入口 `mewcode/cli.py`

- 解析命令行参数，从环境变量读 API key / 模型名 / 接口地址 / 工作区目录
- 没有 key 就直接报错退出，并提示可以先跑 `--demo`
- 组装三件套：`OpenAICompatibleClient`（模型）、`ToolBox`（工具）、`Agent`（主循环），
  然后调用 `agent.run(任务)`

要点：入口只负责组装，不含任何 Agent 逻辑。

## 第 1 站：主循环 `mewcode/agent.py`

`Agent.run()` 是整个项目的心脏，做四件事：

1. 把 system prompt 和用户任务放进 `messages` 列表
2. 循环调用模型：模型要么给出最终文本（结束），要么给出 `tool_calls`（继续）
3. 把每个 tool_call 交给 `_execute()` 执行，结果以 `role=tool` 的消息追加回 `messages`
4. 三个护栏全程生效：
   - 步数超过 `max_steps` → 停，原因是 `max_steps`
   - 同一工具+同一参数出现超过 `repeat_limit` 次 → 停，原因是 `repeated_calls`
   - 工具执行出错 → 不抛异常，转成 `{"ok": false, "error": ...}` 回传给模型

一次正常运行的 messages 大致长这样：

```
system    你是 MewCode……
user      在当前目录创建一个冒泡排序脚本并运行验证
assistant tool_calls: [write_file(sort.py, ...)]
tool      {"ok": true, "result": "wrote ... chars to sort.py"}
assistant tool_calls: [run_shell("python3 sort.py")]   ← 执行前会先请用户确认
tool      {"ok": true, "result": "exit_code=0\n..."}
assistant 已创建并验证通过（无 tool_calls，循环结束）
```

## 第 2 站：工具层 `mewcode/tools.py`

模型说“想做什么”，工具层决定“能不能做、怎么做”：

- `Workspace.resolve()`：所有文件路径先解析成绝对路径，
  再检查是否还在工作区根目录之下——`../` 逃逸在这里被拦
- `run_shell()`：先过危险命令黑名单，再看是否在只读白名单里，
  都不是就调用确认回调（CLI 里是终端 y/N 询问）
- 每个工具的入参/出参都是普通字符串，出错统一抛 `ToolError`，
  由主循环的 `_execute()` 接住并转成结构化反馈

要点：安全策略不写在 prompt 里求模型自觉，而是写在代码里强制执行。

## 第 3 站：模型层 `mewcode/llm.py`

- `LLMClient` 是协议（接口），主循环只依赖它，所以换模型不用改主循环
- `OpenAICompatibleClient` 只用标准库发 HTTP 请求并开启 `stream=True`
- 流式响应里，一个 tool_call 会被拆成很多碎片到达：
  函数名可能只来一次，`arguments` 是一段段字符串，按 `index` 分组——
  `assemble_stream()` 负责把碎片拼回完整的 `ToolCall`
- `iter_sse_json()` 负责把原始 SSE 行流过滤、解码成 JSON 对象
- `FakeLLM` 按脚本回放回复，让 demo 和全部测试可以离线运行

## 测试在测什么（tests/，19 项）

- `test_tools.py`：读写往返、路径逃逸拦截、grep、shell 的放行/拦截/拒绝确认
- `test_llm_stream.py`：文本碎片拼接、工具调用碎片拼接、两个并行调用按 index 分开、坏 JSON 能被识别
- `test_agent.py`：完整写文件流程、**错误反馈后模型改参数恢复**、坏参数变错误反馈、
  步数上限生效、重复调用被检测、shell 端到端

## 想继续练手的话

按难度递增的三个真实改进点（做完任意一个都值得一次提交）：

1. 给工具层加一个 `list_files` 工具（列目录），记得同时加 schema、注册和测试
2. 给主循环加一个简单的 Todo 规划工具
3. 做一个小评测集：3–5 个固定任务（写脚本/修 bug/补函数），
   用 FakeLLM 或真实模型统计通过率和平均步数
